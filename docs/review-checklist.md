# 审核清单（维护者用）

社区包靠人工审核把关。CI 只保证**格式**对；这份清单看的是**内容该不该进画廊**。
一个 PR 过了下面每一条才合并。

## 先看格式（CI 应该已经绿了）

- [ ] CI 绿勾：`check.py` 全 `ok`，索引可复现。
- [ ] 目录名 = `id`，形如 `<handle>.<slug>`，不是 `keysmith.` 开头。
- [ ] 有边车 `packs/<id>.meta.json`，`author.handle` 与 id 第一段一致。

## 再看内容

- [ ] **合法合规**：不含违法内容，不含攻击性/仇恨内容，不是用来绕过某个工具安全策略的越狱提示词。这一条一票否决。
- [ ] **名副其实**：包做的事和 `name` / `summary` 说的一致，没有夸大或误导。
- [ ] **有实际价值**：是一个真能用的提示词/规则，不是占位、灌水或纯广告。
- [ ] **署名与出处清楚**：`author` 可信；若是改编自他人内容，`source_url` 指明来源且授权允许再分发。
- [ ] **license 合理**：`pack.json` 声明了 license，且与内容来源不冲突。
- [ ] **不冒充官方**：不自称 official/官方，不碰 `keysmith.` 命名空间，文案不误导用户以为是官方出品。
- [ ] **语言质量**：中文/英文文案通顺，卡片 `summary` 读得懂。

## 决定

- 内容 OK → approve 并合并（CODEOWNERS 要求你 approve）。
- 小问题（文案、分类、license 字段）→ 请作者改，或你直接 push 到该 PR 分支。
- 内容不合适 → 说明理由后关闭。越界内容直接关，不解释实现细节。

## 合并之后

- 阶段 1 上线后，合并会触发官网画廊重建（读 `community-index.json`）。
- 已合并的 `id`+`version` 内容不可改；作者要改必须升 `version` 再开 PR。
