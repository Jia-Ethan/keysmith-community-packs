Draft a pull-request description from the diff between this branch and its base.
Read the whole diff first. Write for a reviewer who has not seen the change.

Use these sections, and drop any that would be empty:

## What
One or two sentences on what this PR does, in plain language.

## Why
The problem or motivation. Link the issue if the branch name or commits mention
one.

## How
The key decisions a reviewer needs to follow the change — the approach, any
tradeoff, anything non-obvious. Skip the line-by-line; the diff has that.

## Testing
What you ran and what you checked by hand. Be specific: commands, cases.

## Risk
What could break, what to watch after merge, and how to roll back. Write "low,
isolated change" if that's the honest answer.

Keep it tight. A reviewer should know within thirty seconds whether to start.
